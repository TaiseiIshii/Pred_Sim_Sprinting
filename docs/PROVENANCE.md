# PROVENANCE — commit & data traceability

This document is the authoritative provenance record for the validation study. It resolves the
discrepancy that the historical `Results/Validation_Master/manifest.csv` records commit `3da75fc`
while the analysis scripts that produced it were only *committed* at `bb0433a`.

## 1. Timeline (verified via `git show -s` and `git diff`)

| Time (JST, 2026-08-15) | Event |
|---|---|
| 14:34:53 | commit **`3da75fc`** (parent) |
| 15:55:00 | validation analysis run → `manifest.csv` stamped `commit=3da75fc` (repo HEAD then). Analysis scripts existed only as **uncommitted** working-tree files. |
| 18:20:12 | commit **`bb0433a`** (HEAD) adds `analysis/validation/*`, `Results/Validation_Master/*`, and validation docs (50 files, +5167 lines, 0 deletions). |

Therefore `manifest.csv`'s `commit` column = **repo HEAD at analysis runtime**, not the commit that
contains the analysis code. A third party reproducing the analysis needs **`bb0433a`** (where the
scripts live). The scripts committed at `bb0433a` are byte-identical to those that ran at 15:55.

## 2. Three-commit model (why we do not blindly relabel to HEAD)

Per the Phase 1.1 rule "if a result was generated by older code, do not simply replace the SHA",
each result is attributed to three separate commits:

- **simulation_commit** — the code that produced the source `.mat`.
- **analysis_commit** — the code that computed the metric CSVs/figures from the `.mat`.
- **documentation_commit** — the commit (or working-tree state) of the prose that cites the numbers.

### 2.1 simulation_commit
`git diff` evidence:
- `git diff 59877aa..bb0433a -- ExternalFunctions MuscleModel Polynomials CollocationScheme` → **empty**
  (the numerical DAE/muscle/collocation path is unchanged).
- `git diff 3da75fc..bb0433a -- MainFunctions/main_pred_sim_sprinting.m` → **empty** (identical).
- `git diff 59877aa..bb0433a -- MainFunctions/main_pred_sim_sprinting.m` → only (a) a `PelvisShift_`
  token regexp that is backward-compatible for plain conditions, (b) a **new** combined
  `_athSh/_athWk` block that only affects those new conditions, (c) one comment/print encoding fix
  (`±`→`+/-`, off the numerical path). The diff itself states "every non-combined condition is
  byte-for-byte unchanged."
- `wJ(13)`, `paretoStudy`, and `run_ham_pareto_sweep.m` first appear at **`59877aa`**.

Attribution:
| Condition group | simulation_commit | Rationale |
|---|---|---|
| HamPareto (Nom/Sh/Wk), load-penalty objective | `59877aa` | penalty path introduced here; numerically identical through `bb0433a` |
| Nominal, PelvicTD(wide), PelvicShift/Tilt, Morphology (HamFascicle/HamStrength), Haralabidis TD | `59877aa` | baseline max-performance framework; numerically identical `59877aa..bb0433a` |
| `PelvisShift_m02_athSh` (combined, 15-Aug-2026) | `bb0433a` | requires the combined `_athSh` block added between `59877aa..bb0433a` |

> The source `.mat` files are **not** committed to git (they are large binaries, 78 files ≈ 384 MB).
> They are pinned by **SHA256** in `manifest.csv` / `manifest_provenance.csv`. The simulation_commit
> above is the code that *reproduces* them (subject to solver/BLAS nondeterminism).

### 2.2 analysis_commit
All metric CSVs and figures in `Results/Validation_Master/` were produced by
`analysis/validation/*` (engine `ham_load_metrics.py` v1.0.0), first committed at **`bb0433a`**.
→ `analysis_commit = bb0433a` for every output row.

### 2.3 documentation_commit
The prose (`docs/*.md`) currently under revision for the thesis freeze is on **`bb0433a` +
uncommitted working-tree edits (2026-08-15)**. After the human commits the freeze, replace with the
new SHA. Recorded as `documentation_commit = bb0433a+uncommitted-2026-08-15` in
`manifest_provenance.csv`.

## 4. How a third party verifies an output number

1. Open `docs/PAPER_RESULTS_FREEZE.md`; find the claim → figure/CSV cell.
2. In `output_hashes.csv`, confirm the CSV/PNG SHA256 matches the shipped file.
3. In `manifest_provenance.csv`, map the condition → `source_file` + `source_sha256` +
   `simulation_commit` + `solver_status` + `mesh_N` + achieved speed/tilt.
4. If the `.mat` is available (see `DATA_AVAILABILITY.md`), confirm its SHA256, then rerun the
   analysis script at `analysis_commit` (`bb0433a`) to reproduce the CSV.
5. If the `.mat` is not available, the number is still traceable to a pinned hash + commit; the
   `.mat` can be regenerated with the documented MATLAB command at `simulation_commit`.
